# 喵喵大总结

版本：1.2.1 | by NUE-喵喵电波

喵！这是 mewo 系列的 SillyTavern 大总结扩展。默认使用酒馆主 API，也可以选自己配置的 OpenAI 兼容副 API；每个角色卡的聊天档一个世界书条目，总结保存确认后，只隐藏一次旧楼层。

## 1.2.1 更新喵

- 主/副 API 返回长度截断、内容过滤或未完成状态时，不覆盖已有总结、不隐藏消息；非空正文显示在概览的“未完成的总结结果”，可复制。本页暂存，刷新后清除。
- 隐藏前增加一次原生提示词预览：确认当前世界书条目通过激活与预算检查，且正文经过世界书正则后能在最终提示词中找到。失败时保留已保存的总结和原文，调整预算、预设或正则后可“只重试隐藏”，不再次调用模型。预览不修改聊天消息，也不改变世界书预算设置。
- 世界书读回与自定义提示词后处理请求有 30 秒超时；任务取消和切档会中止本任务的读回等待。已经发出的宿主写入仍等待完成，避免旧写入覆盖新聊天；写入结果未确认时暂停自动重试，可点概览底部的世界书刷新按钮或重新打开聊天确认。
- 更换世界书但设置保存失败时，重新同步原世界书的当前存档激活状态，保留未保存表单。若连接故障导致恢复也无法确认，会明确提示重新同步。
- 普通总结复用准备阶段读取的世界书，保留生成后的冲突检查及两次保存读回。隔离场景的一轮总结由 7 次整本读取降至 5 次，列表刷新由 5 次降至 2 次（不计界面与挂载刷新）；分支初始化后仍重新读取，避免覆盖期间的新改动。
- 副 API 密钥保存方式保持原样。

## 1.2.0 更新喵

- 猫咪手账插画用于悬浮入口、标题栏和暂无记录时的插画；使用随扩展打包的透明素材，适配深浅主题，不需要外部图床。
- 界面重新整理为“概览 / 设置 / 提示词 / 记录”。概览突出当前聊天、隐藏与保留范围，以及手动总结、仅合并、恢复操作；高级配置折叠收纳，颜色跟随酒馆主题。
- 悬浮窗口和扩展页共用同一套控件。收起或收回扩展页不会丢失草稿、取消任务或创建第二个面板。标题栏聚焦后可用方向键移动，Shift 加速；Esc 收起窗口。
- 设置和提示词分别提示未保存状态，增加“撤回修改”。历史记录支持“阅读 / 原文”切换和复制；阅读使用酒馆自带的净化库处理 HTML，缺少库时退回纯文本。
- 聊天切换、消息发送或编辑后刷新概览，不额外调用模型。窄屏自动限制浮窗边界，避免窗口被移出屏幕；隐藏失败时展开恢复入口。

- 保留数量明确按“消息条数”计数：20 条消息通常约为 10 轮问答。界面分别显示总结来源终点、隐藏计划终点、已保存的实际运行配置，以及当前阶段、耗时和取消按钮。
- 设置、界面模板、宿主导入、世界书读写、任务阶段和纯数据规则拆为独立模块。普通总结继续使用原生 quiet 生成与保存读回确认流程。

## 当前实现

- 启用插件并开启“自动总结”时，打开聊天存档及每次普通 AI 回复结束后，组装当前完整提示词并计算 token；达到默认 60000 阈值时开始后台大总结，无需用户再次发送。
- 每次超过阈值只触发一轮；隐藏楼层使上下文低于阈值后，下一次越过阈值才会再次触发，避免大总结自身很长时每轮重复总结。总结后仍超限，会提示并暂停连续自动总结，重新打开同一聊天档也不会重复尝试。
- 每轮总结默认保留最新 20 条消息原文，默认世界书名为“喵喵大总结世界书”；阈值、保留数量、插入深度、世界书名和提示词均可修改。保留数量只决定保存后隐藏到哪里，不会提前排除最近消息，也不会持续维持可见消息数量。升级保留已有世界书名称，避免原总结失去关联。
- 提供“多次大总结”和“合并大总结”两种模式，默认提示词使用用户提供的对应中文版本，支持 SillyTavern 宏。
- 两种模式分别保存自定义提示词。编辑后点击“保存修改提示词”生效；“回到默认提示词”只更新编辑框，仍需保存。刷新、重启、切换角色和修改普通设置都不会替换已保存的模板。旧版自定义提示词保留在多次模式，未改动的旧 ELLA 默认提示词会更新为新默认。
- 总结通过酒馆原生 `Generate('quiet')` 流程运行，经过发送时的正则、世界书条件、扩展拦截器及 EJS/MVU 处理，不新增可见聊天楼层。默认沿用主 API、当前模型和预设；选择副 API 时，仅本次总结的模型请求改发副 API，预设环境仍由酒馆组装。不抓取页面渲染出来的 HTML。
- 副 API 使用酒馆自定义 OpenAI 后端转发模型列表和生成请求，不从浏览器跨域直连。独立 URL、Key 和模型不会覆盖主连接设置；无密钥服务可留空，不借用主连接密钥。副 API 失败时提示错误，不自动改用主 API。采样、输出长度及提示词后处理沿用当前生成参数。
- 默认把大总结指令放在完整提示词最后，位于所有预设和 EJS 尾部内容之后，聊天补全中为最后一条 user 指令。也可选择角色定义之前、之后或聊天深度 @D，并选择 system/user/assistant；D0 + system 为系统层深度 0。层级注入使用酒馆原生接口，仅总结期间存在，完成、失败或切档后清理。
- 保存前读取酒馆当前“推理内容格式化”的前缀/后缀，去掉它们包裹的内容，保留外部正文（包括完整 `<details>`）。例如配置 `<star_cot>` 和 `</star_cot>`，该段不会写进世界书或本轮历史。只有推理、没有正文时不保存、不隐藏楼层。同步时也清理已有条目/历史中匹配当前完整推理标签的段落；没有可恢复正文的旧记录保留。
- 为兼容将自定义总结格式过滤为空的输出正则，仅观察本次总结对应的非流式 API 响应副本来提取正文；不额外调用模型、不输出响应日志，结束后恢复请求处理。
- 回复结束后的 token 检查、后台生成、世界书保存及隐藏楼层期间暂停发送；可以保留输入框中的草稿，完成后继续对话。
- “启用”开关切换后立即生效并保存到酒馆设置。取消勾选会停止自动检查、切档同步和计数刷新，取消待触发及正在运行的总结，并停用所有插件总结条目；手动总结、合并和恢复也需先启用。关闭状态启动时会清理旧版残留一次，之后不在后台检查世界书；仍可主动打开“记录”页只读查看历史。
- “自动总结”需要保存设置后生效。单独关闭它不会停用世界书中的已有总结，也不影响手动总结、合并、恢复和存档隔离。
- 输入框中的所有 `/` 命令均交给酒馆原生解析，包括 `/hide`、`/unhide`、管道、宏、闭包及其他插件注册的命令。插件不代替解析、不清空命令输入、不等待生成事件释放锁。本地命令不会触发总结；命令若调用模型，在总结处理期间由酒馆原生生成拦截器取消该次模型生成，处理结束后可重新执行。酒馆本身正在生成时的输入限制仍由酒馆管理。
- 自动和手动任务显示准备、生成、保存、隐藏或恢复阶段及耗时。点击“取消本次任务”会停止后续处理；已经保存的总结保留。正文读回确认成功后才提示保存成功，已保存但隐藏失败时可只重试隐藏。
- 生成后及正式保存前检查聊天身份和原楼层；切档或手动调整楼层时不会将过时结果写入世界书，也不会继续自动隐藏。若保存之后发生变化，保留已保存记录并提示没有隐藏楼层。
- 多次模式：每轮只总结新增剧情，并追加到同一聊天档的原条目。第二次、第三次继续写进第一次创建的条目，注入正文包含累积总结。
- 合并模式：每轮将已有总结和新增剧情汇总，使用新 AI 回复替换同一条目的注入正文。切换模式从下一轮生效。
- 每轮 AI 正文保存在条目内部的历史记录中，目录可以查看当前注入全文或逐轮正文，以及来源终点和隐藏计划。撤销的记录保留正文并标记“已撤销”，不再参与注入；删除单轮会按剩余有效历史重建正文。删除历史会清除该条目的恢复信息，已隐藏的消息不会自动恢复。
- 插件启用时，切换角色卡或聊天存档会真正禁用其他档的条目，仅当前档的条目蓝灯启用；同步结束前暂停发送，并刷新已经打开的世界书编辑器。
- 新建及已有大总结条目统一勾选“防止进一步递归”。旧版同一聊天档的多个条目自动迁入原条目，历史 AI 原文保留。
- 每次新总结返回非空内容并成功保存世界书后，只执行一次酒馆原生 `/hide 0-终点`。例如最后一楼编号为 666、保留 20 楼时，执行 `/hide 0-646`。之后用户可自由 `/hide`、`/unhide`；切档、修改保留数量、刷新和 token 检查不会重新应用旧总结的隐藏范围。本轮候选范围全被用户隐藏时不重复总结。
- 原生 `/hide`、`/unhide` 保存完成后，只刷新当前实际上下文的 token 计数，并刷新酒馆预设面板的原有计数缓存显示；不会因这次手动调整立即触发总结或再次隐藏，计数超过阈值也一样。命令的参数、角色过滤、管道返回值和错误仍由酒馆处理。关闭插件后不参与计数刷新，命令仍由酒馆自行处理。切档、连续修改或计数失败会丢弃过时计数并释放发送锁。
- 用户发送 `/hide` 或 `/unhide` 时，正在等待的检查/总结会失效，命令仍交给酒馆处理。整个 token 预览组装阶段都标记为预览，阻止模板 `execute` 再次执行斜杠命令；预览成功或失败都会清理标记，不影响真实总结发送时的原生处理。
- UI 分为“概览 / 设置 / 提示词 / 记录”，在扩展页或悬浮窗口中都可使用。目录支持搜索、角色筛选，每页最多 8 个角色，默认仅展开当前角色，并限制目录高度。
- 设置增加“保存设置”和“回到默认设置”。除“启用”开关外，修改或回到默认后需保存才生效；提示词有独立的保存/默认按钮。刷新状态与拉取模型按钮固定横排。
- 启用状态下启动时检查 Git 更新，有更新时标题显示 mewo!!，展开后显示版本和更新按钮；也可手动检查。由用户点击更新，成功后等待当前生成/总结处理完成，再自动刷新 ST，暂存并恢复聊天输入框的草稿。

## 安装

仓库地址：<https://github.com/AYUUKI-K/Mewo-Large-Summary>。在 SillyTavern 的“扩展”页面使用“安装扩展”并粘贴该仓库 URL。扩展后续版本可在 SillyTavern 页面检查，由用户选择是否更新。

## 使用

1. 点击右下角“总结”打开悬浮窗口，也可以在扩展列表展开“喵喵大总结”。顶部“启用”开关立即生效并保存。到“设置”确认自动开关、60000 token 阈值、保留消息条数和运行模式，修改后点击“保存设置”；世界书和指令位置放在“世界书与指令位置”中。“回到默认设置”只更新表单，仍需保存，不重置提示词或删除已有总结。
2. 不需要手动创建世界书。第一次大总结会自动创建并挂载到全局世界书；已有同名书继续使用，其中的其他插件或手写条目不会被覆盖。概览底部显示创建和挂载状态，旁边的刷新按钮可重新检查。
3. 使用副 API 时，在“总结使用的 API”中选择副 API，填写 `https://服务地址/v1` 和 Key。填写完成后自动拉模型，也可点“拉取模型”；从下拉列表选择模型，或选择“手动填写模型名…”后输入完整模型 ID，再点“保存设置”。默认仍使用主 API 喵。
4. 在“提示词”分页选择要编辑的模式，编辑后点击“保存修改提示词”。实际运行模式在“设置”中选择并保存；两个模板独立长期保存，不同模式的未保存草稿只在本次页面会话中保留。
5. 在“概览”点击“立即总结并隐藏旧消息”手动运行，不受自动阈值限制；仍需有可处理的旧消息。只想压缩已有总结时点“仅合并已有总结”，不需要新增聊天。按钮上方显示实际已保存的模式、API 和保留数量，未保存的表单不会改变运行配置。token 是最近一次计数，可用旁边的刷新按钮重新组装计数。
6. 在“记录”中搜索、筛选并阅读当前注入内容或历史正文；“原文”显示模型原始输出，右上角按钮复制原文。需要恢复时，在“概览”展开“恢复与撤销”。关闭总开关时目录保持只读。
7. 出现 mewo!! 时展开插件并点击“更新”，成功后自动刷新。旧版仍显示 New! 时，照常点更新即可。在支持扩展生命周期钩子的 ST 版本中，通过原有扩展管理页更新此插件也会自动刷新。

总结范围由提示词及 SillyTavern 当前生成上下文决定。阈值根据回复结束后酒馆组装的最终提示词计算，使用酒馆当前模型的 tokenizer。自定义聊天补全的提示词后处理也在计数前执行，不使用模型最大上下文容量作为 token 数。插件内会显示最近一次检查结果。

例如：开启自动总结后，本轮发送前为 59000 token，AI 回复后组装为 61000 token，则此时自动总结；保存并隐藏前文后重新计数，低于阈值后恢复下一次自动触发。打开已经达到 80000 token 的存档也会立即检查并触发。版本和署名位于展开区域，折叠时隐藏。

如果 API 或保存失败，会显示错误并解除发送锁；API 无正文或世界书未读回确认时不隐藏楼层。

### 总结范围与保留原文

假设恰好一问一答算一轮，没有额外开场白：聊到 50 轮，共 100 条消息，保留 20 条。普通总结会使用酒馆当前组装的完整上下文，包含最近 10 轮；保存成功后执行 `/hide 0-79`，保留第 80–99 层，也就是第 41–50 轮原文。最近剧情同时出现在总结和原文中，用于衔接与保留细节。

继续聊到 75 轮时，通常由已有总结、保留的第 41–50 轮原文及新增第 51–75 轮组成上下文。多次模式按模板提取新增剧情并追加；合并模式整理成新的完整总结。以上始终受酒馆当前可见消息、预设和上下文组装规则影响；插件不额外设置世界书预算限制。

“仅合并已有总结”是独立操作，只发送当前注入的总结及合并模板，不带当前聊天剧情。主/副 API 路由与生成参数照常沿用配置；普通总结的指令插入位置不用于这一专门操作。

### 恢复与分支

- **只重试隐藏**：用于正文已经保存、隐藏尚未完成或尚未确认的情况。直接完成那次隐藏，不重新付费生成。
- **恢复本轮隐藏的消息**：仅恢复最近一次操作把可见改为隐藏的消息；原先已经隐藏的消息保持原样。它不删除总结，恢复后原文和总结可能同时进入上下文。
- **撤销最近一次总结**：恢复上一次的注入正文，保留本次 AI 正文供查阅。消息可见状态不变，需要时再恢复原文。自动总结会等待新的聊天消息，避免刚撤销就立刻重做。

恢复仅针对最近一次操作；新的总结或合并会替换这份恢复信息。修改原文、切换 swipe、手动执行 `/hide` 或 `/unhide` 后，自动恢复会拒绝覆盖后续操作。关闭总开关也会使旧的消息恢复失效，因为插件无法持续观察关闭期间的改动；仍可使用酒馆原生命令手动调整。手动修改世界书正文后，插件也不会用撤销结果覆盖它。

新分支单独保存总结，不会改写主线正文或历史。新记录会保存总结来源的终点与原文指纹，只有验证属于分支之前的内容才会继承。旧版记录只有隐藏终点，无法据此判断是否含分叉后的剧情，因此会提示“从分支原文重建（含隐藏消息）”，由用户点击后调用模型。重建会读取这个分支的全部消息原文，包括隐藏消息；消息少于保留数量时不执行隐藏。旧总结和历史仍保留在原存档中。

## 边界

- 自动触发针对角色卡的单人聊天；群聊不触发。
- 自动触发检查普通生成和会话续写；重试、再生成、滑动和后台静默生成不会触发总结。
- 如果主模型的最大上下文小于阈值，触发条件无法达到，可调低阈值。
- 副 API 默认支持 OpenAI 兼容接口，不包含原生 Anthropic/Gemini 接口。因为沿用酒馆原生生成流程，运行时需保持酒馆当前主连接可用；实际总结模型请求只发往副 API。上下文预算与阈值计数仍由当前酒馆配置决定，副模型需能容纳该上下文。

本次接口核对以 SillyTavern 官方 1.19.0 源码为参考，分支身份使用其聊天 `integrity` 字段；没有该字段的宿主按存档名变化保守隔离。回归测试和模拟宿主检查不代表真实宿主兼容性验证；用户实际安装版本、第三方插件组合和主/副 API 仍需在酒馆中验证。

隐藏前确认使用 1.19.0 的 `WORLDINFO_SCAN_DONE` 及世界书正则接口。缺少接口时保留原文；第三方模板若进一步改写总结、导致无法确认完整正文，也会保守停止隐藏并说明原因。此检查确认当前预览的注入，不保证用户之后修改预算、预设或其他世界书时仍能注入。

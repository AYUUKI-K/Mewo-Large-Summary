# 喵喵大总结

版本：1.2.15 | by NUE-喵喵电波

喵！这是 mewo 系列的 SillyTavern 大总结扩展。默认使用酒馆主 API，也可以选自己配置的 OpenAI 兼容副 API；每个角色卡的聊天档一个世界书条目，总结保存确认后，只隐藏一次旧楼层。

## 1.2.15 副 API 独立默认参数

- 副 API 不再继承主 API 的采样参数、停止词、随机种子和输出长度。采样参数不发送，由副接口使用自身默认值；总结输出上限独立固定为 8192 token，避免主 API 预设中的参数造成副模型报错或提前停止。
- 酒馆组装的上下文、总结模板与提示词后处理继续保留；主 API 总结仍按当前连接及预设生成。副 API 的 URL、Key、模型和插件自己的流式开关保持原有配置，无需重新保存。

## 1.2.14 靠边精简与 token 常驻

- 将收起的猫咪入口拖到左右边缘附近并松手，自动吸附为 token 小标签；点击打开完整面板，收起后回到停靠位置，拖离边缘松手恢复猫咪入口。展开的操作面板保持原有拖动方式。
- “设置 → 界面 → 靠边自动精简”默认开启，立即生效并记住当前浏览器的选择；旧位置不会在升级后自行吸附，只有主动拖动靠边才触发。关闭开关会恢复普通入口。
- 停靠方向和相对高度在刷新、屏幕旋转与视口缩小时保留。精简标签至少 64×44px，任务处理中保留状态提示；方向键可移动，朝屏幕内侧移动可脱离吸附，Home 复位。
- token 沿用最近一次计数，不额外发起请求。缩写保留一位小数，例如 `12,345 → 12.3k`；悬停提示和无障碍名称包含完整计数，尚无计数显示 `—`，已知零值显示 `0`。完整面板仍可查看及刷新计数。
- 保留手机设置面板可见时的临时入口避让，以及“关闭悬浮窗”后的显示偏好。
- 触屏拖动后立即轻点也能打开，取消手势不会误打开窗口。浏览器模拟与真实宿主的验证范围见 [兼容性说明](COMPATIBILITY.md)。

## 1.2.13 TauriTavern 后处理预览兼容

- TauriTavern 的后处理预览接口缺失（404/501）或返回 HTML 时，使用与已核对 TT Rust 实现对应的本地预览。支持合并、半严格、严格、单条消息及对应保留工具模式，用户可保留当前“自定义提示词后处理”设置。
- 仅处理预览副本，用于自动总结计数及隐藏前验证；生成请求继续使用宿主原有后处理。不重发模型请求，不改写连接设置，也不跳过世界书激活、预算或正文覆盖检查。
- 正常的宿主预览接口优先；普通 SillyTavern 不使用 TT 回退。认证、服务错误、取消、超时、损坏 JSON 继续报错。未知模式、异常内容格式或无法可靠恢复的媒体与姓名组合会停止验证。
- JSON 接口错误显示请求路径、状态码及 HTML/空响应/格式异常的说明。兼容依据和未验证范围见 [兼容性说明](COMPATIBILITY.md)。

## 1.2.12 常用操作与结果保留

- 概览突出当前可执行的下一步：确认写入结果、继续恢复原文、从原文重建、只重试隐藏或查看已完成的总结。自动总结暂停时直接说明原因；输入覆盖检查失败后，仍可在调整上下文后手动重试普通总结。
- 提示词页突出“实际运行模板”，可直接跳到“编辑当前运行模板”；原保存按钮改为“仅保存模板”，保存其他模板时说明当前仍使用哪一份。“保存并使用此模板”继续保留其他模板及设置草稿。
- 当前总结、选中的历史正文和未完成正文都可下载为 UTF-8 文本文件，保留原始内容。
- 自动总结复用本次已有的前后计数，显示整理前后 token 及减少或增加量；来源、配置变化或缺少可靠前值时不作对比。手动总结通常只显示整理后计数，不新增模型请求或计数预览。
- 未完成正文按存档保存在当前浏览器中，每个存档保留最新一份。生成期间约每秒保存一次，正常离开页面时补存；中断、取消或生成完成时立即保存，世界书写入确认后清理。草稿不会自动注入、隐藏或续写，可复制、下载或主动删除。存储失败保留本页正文并提示导出，也可重试本地存储。
- 新增“撤销本次整理并恢复原文”，一次确认后退回此前注入内容，再恢复本轮实际隐藏的消息。若恢复中断，概览可“继续恢复本次原文”，刷新后仍有效；不会重复撤销或调用模型。原来分别撤销和恢复的入口保留。
- 保留原文/可见性校验、写入读回确认、发送锁及旧版本保护，默认 60000 与完整上下文用法不变。实际验证范围见 [兼容性说明](COMPATIBILITY.md)。

## 1.2.11 概览、模板启用与手机避让

- 概览按实际消息状态区分“已经隐藏”“还将隐藏”“继续保留”。没有可处理旧消息时，普通总结按钮禁用并显示原因；仅合并已有总结沿用原条件。恢复原文不会把已总结消息重新算成待总结内容。
- 总结成功显示本次新隐藏、保留原文的实际数量；沿用原有总结后计数补充当前 token，不增加模型调用或预览。隐藏失败明确显示“总结已保存，隐藏未完成”，可只重试隐藏。旧记录没有的结果计数不补成零。
- 提示词页新增“保存并使用此模板”，保存当前模板并启用对应风格、模式。其他三份模板草稿和设置页草稿保留；普通保存仍只更新模板。保存失败保留草稿并恢复原运行配置。
- 手机宽度（≤600px）下，本插件的扩展面板出现在视口时，猫咪入口临时收起；面板离开视口或收起后恢复。用户主动关闭入口的偏好保留，桌面行为不变。
- 保留 1.2.10 的输入覆盖、原文变更和预算提示保护，默认阈值仍为 60000，继续使用完整上下文及原有两套模板。验证范围见 [兼容性说明](COMPATIBILITY.md)。

## 1.2.10 记忆有效性与输入检查

- 普通总结在发送前检查当前可见原文是否进入宿主组装的提示词。检测到裁剪或缺少覆盖信息时停止，不调用该次模型、不保存总结、不隐藏消息；概览提供手动重试和从当前原文重建的入口，自动总结暂停，避免反复失败。
- 修改、删除或切换已总结原文的 swipe 后，显示“记忆待更新”，暂停自动总结、普通总结及仅合并。点击“从当前原文重建（含隐藏消息）”可重新生成；重建成功前旧总结仍继续注入，原文和历史记录保留。撤销重建会重新检查旧总结是否过时。
- 自动阈值达到或超过主连接可用输入预算时给出提示；默认阈值仍为 60000，不自动修改上下文、阈值或压缩模式。上下文充足时没有此提示。
- 输入检查不添加原文标记、不额外调用模型。它检查宿主组装阶段的文本覆盖，不评估总结事实质量，也不保证后续第三方模板不会改变资料；详细边界见下方及 [兼容性说明](COMPATIBILITY.md)。

## 1.2.9 兼容适配

- 适配目标为 SillyTavern 1.14–1.18；已核对各系列的 `.0` 官方标签。1.14–1.17 缺少 context 世界书名称接口时，从宿主的世界书模块读取实时列表，避免把已有书误判为不存在。
- 1.14 缺少世界书扫描完成事件时，先验证正常提示词，再用临时副本中的唯一标记验证条目来源。两次均为原生 dry-run，不调用模型、不把标记保存进世界书。预算不足、正则移除正文或无法确认来源时仍不隐藏原文；1.15 起沿用扫描事件确认。
- 总结取消、拉模型和检查更新不再依赖较新 WebView 才有的 `AbortSignal.any/timeout/throwIfAborted`，保留宿主原有 fetch 桥接，结束后清理取消监听。
- TauriTavern Canary `21477e44e0ec`（2026-10-12）可作为有条件试用目标：1.2.9 当时要求主连接的“自定义提示词后处理”设为“无”；1.2.13 已补充缺失预览接口的本地兼容，支持范围见上方更新说明。副 API 仍限 OpenAI 兼容接口。
- 验证包括 213 项隔离回归、6 个宿主源码契约检查及 1.14/Tauri 接口形态的浏览器模拟流程。尚未对真实五版酒馆、Tauri 安装包或付费模型做端到端验证；详细范围和固定源码见 [兼容性说明](COMPATIBILITY.md)。

## 1.2.6 更新喵

- 展开窗口的标题栏新增“×”关闭按钮，关闭时同时隐藏窗口和猫咪入口，刷新后保持关闭。原有“−”和 Esc 继续只收起窗口；猫咪入口保持小巧。
- 设置 → 界面新增“显示悬浮入口”开关，立即生效并记住当前浏览器的选择；也可以点击扩展面板顶部的窗口图标重新打开。关闭不会停用插件、取消总结任务或丢失未保存的草稿，窗口位置与大小继续保留。
- 猫咪入口用一个小标签显示“自动 / 手动 / 停用”；展开窗口的标题下显示插件和自动总结的两项开关状态。插件关闭但自动开关仍开启时显示“自动暂停”，悬停可查看开关仍开启的说明。状态以已生效的设置为准，自动总结的修改保存后同步。

## 1.2.5 更新喵

- 总结默认启用独立的流式接收，支持聊天补全主 API 和 OpenAI 兼容副 API，不受普通聊天流式开关影响。继续使用酒馆原生 quiet 流程组装提示词，不向聊天追加模型回复；其他主 API 和已知不支持流式的模型沿用完整响应。
- 浮窗和扩展面板显示等待响应、模型思考、已收到的正文字数、耗时，以及长时间未收到数据的提示。可展开查看正在生成的正文；推理字段不写入总结，不显示虚假的完成百分比。
- 手动取消、连接中断、流式数据损坏、输出截断或模型报错时，已收到的正文留在当前存档的“未完成的总结结果”中，可查看和复制。1.2.5 当时仅在本页暂存；1.2.12 起改为浏览器持久草稿。成功保存新总结后自动清除。半成品不会写入世界书或触发隐藏，缺少正常结束标志的连接关闭也视为中断。
- 兼容酒馆代理不转发流式响应头，以及部分接口忽略流式参数、直接返回 JSON 的情况；不会自动重发模型请求。设置 → API 与模型中可关闭“流式接收总结”，兼容不接受流式参数的服务。
- 流式降低等待整份正文造成的超时风险；首个数据包过慢、模型思考时无数据或中转缓冲仍可能超时。此版本不分段、不自动续写中断结果。

## 1.2.4 更新喵

- 提供“传统详述”和“结构记忆”两套提示词风格，各有新增、合并模板，共四份，分别编辑保存。默认沿用传统详述，已有自定义提示词保留在传统详述中。在设置页选择实际运行风格和模式，提示词页的选择只改变编辑对象。
- 传统详述保留原有“大总结 + 角色表”格式，以及时间、事件、细节、对话与内心戏、行为、情感变化和事件后续；重写要求，明确各字段只补充新信息，避免同一事件反复填报。
- 结构记忆按“已发生因果 / 人物与关系 / 约定与未决事项 / 知情范围与秘密 / 接续状态 / 长期关键事实”分类，空栏目省略；保留关系变化依据和重要短引，合并重复日常。
- 新增模式记录变化、明确纠正和约定状态更新；合并模式保留仍有效的完整记忆，并替换过期的状态与数值。事实、说法、推测和计划分开，知情范围不默认扩散给其他角色。
- 移除对未定义的“角色表规范”和关系图的依赖。总结轮次与消息覆盖范围由插件概览及历史元数据呈现；模型只记录资料明确的剧情时间或末尾场景，不自行编造编号。
- 未自定义的历版默认模板自动迁移为优化后的传统详述，包括 1.2.3 已删除开场指令的模板。可在提示词页选择风格和模式后点击“回到默认提示词”并保存，只重置正在编辑的一份。模板更新不重写已有世界书或历史记录；新风格从下次总结生效，已有总结可用“仅合并已有总结”重新整理。

## 1.2.3 更新喵

- 两种默认总结模板移除“停止剧情，停止输出其他所有内容，开始执行……”开场指令，任务身份继续由请求层统一声明，并明确要求不复述任务说明、模板要求和资料边界标记。
- 已保存且未自定义的旧默认模板自动迁移并保存；自定义模板保留原文。已有世界书正文与历史记录不会因模板迁移被重写；如果旧结果已混入开场指令，可在世界书中编辑该条总结，删除多余指令。

## 1.2.2 更新喵

- 修复酒馆原生按钮的最小内容宽度导致中文逐字换行的问题，覆盖桌面、手机、扩展设置页和浮窗中的保存、恢复、撤销等按钮。极窄面板的保存操作改为两行按钮，每个按钮的文字仍横向显示。
- 猫咪入口也能拖动，点击才展开；标题栏继续支持鼠标与触屏拖动。手机窗口留出可移动空间，旧的满屏尺寸自动收紧，位置记在当前浏览器中。拖动后不误触打开；聚焦入口或标题栏可用方向键微调、Shift 加速、Home 复位。
- 默认总结模式改为“独立总结任务”：仍由酒馆组装当前聊天、旧总结、世界书及模板处理后的上下文，再把这些内容作为资料交给模型；仅本次总结模板作为系统任务执行，避免角色预设要求模型先续写剧情。用户保存的模板保持原样，普通聊天不受影响；其他指令位置仍使用原生层级注入。
- 明显混入完整章节正文或变量更新块的输出不写入世界书、不隐藏原文，显示在“未完成的总结结果”供查看；不自动重试模型。此检查识别特定完整输出块，不能判断所有自然语言中的虚构或错误。

## 1.2.1 更新喵

- 主/副 API 返回长度截断、内容过滤或未完成状态时，不覆盖已有总结、不隐藏消息；非空正文显示在概览的“未完成的总结结果”，可复制。1.2.12 起改为浏览器持久草稿。
- 隐藏前增加一次原生提示词预览：确认当前世界书条目通过激活与预算检查，且正文经过世界书正则后能在最终提示词中找到。失败时保留已保存的总结和原文，调整预算、预设或正则后可“只重试隐藏”，不再次调用模型。预览不修改聊天消息，也不改变世界书预算设置。
- 世界书读回与自定义提示词后处理请求有 30 秒超时；任务取消和切档会中止本任务的读回等待。已经发出的宿主写入仍等待完成，避免旧写入覆盖新聊天；写入结果未确认时暂停自动重试，可点概览底部的世界书刷新按钮或重新打开聊天确认。
- 更换世界书但设置保存失败时，重新同步原世界书的当前存档激活状态，保留未保存表单。若连接故障导致恢复也无法确认，会明确提示重新同步。
- 普通总结复用准备阶段读取的世界书，保留生成后的冲突检查及两次保存读回。隔离场景的一轮总结由 7 次整本读取降至 5 次，列表刷新由 5 次降至 2 次（不计界面与挂载刷新）；分支初始化后仍重新读取，避免覆盖期间的新改动。
- 副 API 密钥保存方式保持原样。

## 1.2.0 更新喵

## 当前实现

- 启用插件并开启“自动总结”时，打开聊天存档及每次普通 AI 回复结束后，组装当前完整提示词并计算 token；达到默认 60000 阈值时开始后台大总结，无需用户再次发送。
- 每次超过阈值只触发一轮；隐藏楼层使上下文低于阈值后，下一次越过阈值才会再次触发，避免大总结自身很长时每轮重复总结。总结后仍超限，会提示并暂停连续自动总结，重新打开同一聊天档也不会重复尝试。
- 每轮总结默认保留最新 20 条消息原文，默认世界书名为“喵喵大总结世界书”；阈值、保留数量、插入深度、世界书名和提示词均可修改。保留数量只决定保存后隐藏到哪里，不会提前排除最近消息，也不会持续维持可见消息数量。升级保留已有世界书名称，避免原总结失去关联。
- 提供“多次大总结”和“合并大总结”两种模式，默认提示词使用用户提供的对应中文版本，支持 SillyTavern 宏。
- 两种风格各有新增、合并模板，四份独立保存。“仅保存模板”更新正在编辑的一份；“保存并使用此模板”同时切换运行风格与模式。“回到默认提示词”只更新编辑框，仍需保存。刷新、重启、切换角色和修改普通设置都不会替换已保存的模板。旧版自定义提示词保留在传统详述中，未改动的旧默认提示词会更新为新默认。
- 总结通过酒馆原生 `Generate('quiet')` 流程运行，经过发送时的正则、世界书条件、扩展拦截器及 EJS/MVU 处理，不新增可见聊天楼层。默认沿用主 API、当前模型和预设；选择副 API 时，仅本次总结的模型请求改发副 API，预设环境仍由酒馆组装。不抓取页面渲染出来的 HTML。
- 副 API 使用酒馆自定义 OpenAI 后端转发模型列表和生成请求，不从浏览器跨域直连。独立 URL、Key 和模型不会覆盖主连接设置；无密钥服务可留空，不借用主连接密钥。副 API 失败时提示错误，不自动改用主 API。采样使用副接口自身默认值，输出上限固定为 8192 token，不继承主 API 的采样参数、停止词或随机种子；提示词后处理继续沿用酒馆的发送处理。
- 默认使用“独立总结任务”：在预设和 EJS 完成组装后，将当前上下文转换为资料消息，再以 system 指令执行总结模板。原有预设、角色和世界书内容均保留为资料，不再作为本次角色续写的指令；多模态资料保留原有内容块。也可选择角色定义之前、之后或聊天深度 @D，并选择 system/user/assistant；D0 + system 为系统层深度 0。这些高级位置沿用原生层级注入，仅总结期间存在，完成、失败或切档后清理。
- 保存前读取酒馆当前“推理内容格式化”的前缀/后缀，去掉它们包裹的内容，保留外部正文（包括完整 `<details>`）。例如配置 `<star_cot>` 和 `</star_cot>`，该段不会写进世界书或本轮历史。只有推理、没有正文时不保存、不隐藏楼层。同步时也清理已有条目/历史中匹配当前完整推理标签的段落；没有可恢复正文的旧记录保留。
- 为兼容将自定义总结格式过滤为空的输出正则，仅观察本次总结对应的非流式 API 响应副本来提取正文；不额外调用模型、不输出响应日志，结束后恢复请求处理。
- 回复结束后的 token 检查、后台生成、世界书保存及隐藏楼层期间暂停发送；可以保留输入框中的草稿，完成后继续对话。
- “启用”开关切换后立即生效并保存到酒馆设置。取消勾选会停止自动检查、切档同步和计数刷新，取消待触发及正在运行的总结，并停用所有插件总结条目；手动总结、合并和恢复也需先启用。关闭状态启动时会清理旧版残留一次，之后不在后台检查世界书；仍可主动打开“记录”页只读查看历史。
- “自动总结”需要保存设置后生效。单独关闭它不会停用世界书中的已有总结，也不影响手动总结、合并、恢复和存档隔离。
- 输入框中的所有 `/` 命令均交给酒馆原生解析，包括 `/hide`、`/unhide`、管道、宏、闭包及其他插件注册的命令。插件不代替解析、不清空命令输入、不等待生成事件释放锁。本地命令不会触发总结；命令若调用模型，在总结处理期间由酒馆原生生成拦截器取消该次模型生成，处理结束后可重新执行。酒馆本身正在生成时的输入限制仍由酒馆管理。
- 自动和手动任务显示准备、生成、保存、隐藏或恢复阶段及耗时。点击“取消本次任务”会停止后续处理；已经保存的总结保留。正文读回确认成功后才提示保存成功，已保存但隐藏失败时可只重试隐藏。
- 生成后及正式保存前检查聊天身份和原楼层；切档或手动调整楼层时不会将过时结果写入世界书，也不会继续自动隐藏。若保存之后发生变化，保留已保存记录并提示没有隐藏楼层。
- 多次模式：每轮只总结新增剧情，并追加到同一聊天档的原条目。第二次、第三次继续写进第一次创建的条目，注入正文包含累积总结。
- 合并模式：每轮将已有总结和新增剧情汇总，使用新 AI 回复替换同一条目的注入正文。切换模式从下一轮生效。
- 每轮 AI 正文保存在条目内部的历史记录中，目录可以查看当前注入全文或逐轮正文，以及来源终点和隐藏计划。撤销的记录保留正文并标记“已撤销”，不再参与注入；删除单轮会按剩余有效历史重建正文。删除历史会清除该条目的恢复信息，已隐藏的消息不会自动恢复。
- 插件启用时，切换角色卡或聊天存档会真正禁用其他档的条目，仅当前档的条目蓝灯启用；同步结束前暂停发送，并刷新已经打开的世界书编辑器。
- 新建及已有大总结条目统一勾选“防止进一步递归”。旧版同一聊天档的多个条目自动迁入原条目，历史 AI 原文保留。
- 每次新总结返回非空内容并成功保存世界书后，只执行一次酒馆原生 `/hide 0-终点`。例如最后一楼编号为 666、保留 20 楼时，执行 `/hide 0-646`。之后用户可自由 `/hide`、`/unhide`；切档、修改保留数量、刷新和 token 检查不会重新应用旧总结的隐藏范围。本轮候选范围全被用户隐藏时不重复总结。
- 原生 `/hide`、`/unhide` 保存完成后，只刷新当前实际上下文的 token 计数，并刷新酒馆预设面板的原有计数缓存显示；不会因这次手动调整立即触发总结或再次隐藏，计数超过阈值也一样。命令的参数、角色过滤、管道返回值和错误仍由酒馆处理。关闭插件后不参与计数刷新，命令仍由酒馆自行处理。切档、连续修改或计数失败会丢弃过时计数并释放发送锁。
- 用户发送 `/hide` 或 `/unhide` 时，正在等待的检查/总结会失效，命令仍交给酒馆处理。整个 token 预览组装阶段都标记为预览，阻止模板 `execute` 再次执行斜杠命令；预览成功或失败都会清理标记，不影响真实总结发送时的原生处理。
- UI 分为“概览 / 设置 / 提示词 / 记录”，在扩展页或悬浮窗口中都可使用。目录支持搜索、角色筛选，每页最多 8 个角色，默认仅展开当前角色，并限制目录高度。
- 设置增加“保存设置”和“回到默认设置”。除“启用”开关外，修改或回到默认后需保存才生效；提示词有独立的保存/默认按钮。刷新状态与拉取模型按钮固定横排。
- 启用状态下启动时检查 Git 更新，有更新时标题显示 mewo!!，展开后显示版本和更新按钮；也可手动检查。由用户点击更新，成功后等待当前生成/总结处理完成，再自动刷新 ST，暂存并恢复聊天输入框的草稿。

## 使用

1. 点击右下角“总结”打开悬浮窗口，也可以在扩展列表展开“喵喵大总结”。点击“关闭悬浮窗”关闭窗口和入口，“−”或 Esc 只收起窗口；关闭后可从扩展面板顶部的窗口图标重新打开，或到“设置 → 界面”打开“显示悬浮入口”。顶部“启用”开关立即生效并保存。到“设置”确认自动开关、60000 token 阈值、保留消息条数和运行模式，修改后点击“保存设置”；世界书和指令位置放在“世界书与指令位置”中。“回到默认设置”只更新表单，仍需保存，不重置提示词或删除已有总结。
2. 不需要手动创建世界书。第一次大总结会自动创建并挂载到全局世界书；已有同名书继续使用，其中的其他插件或手写条目不会被覆盖。概览底部显示创建和挂载状态，旁边的刷新按钮可重新检查。
3. 使用副 API 时，在“总结使用的 API”中选择副 API，填写 `https://服务地址/v1` 和 Key。填写完成后自动拉模型，也可点“拉取模型”；从下拉列表选择模型，或选择“手动填写模型名…”后输入完整模型 ID，再点“保存设置”。默认仍使用主 API 喵。
4. 在“提示词”分页先看“实际运行模板”，可点击“编辑当前运行模板”直接修改。编辑后点击“保存并使用此模板”即可保存并切换运行配置；“仅保存模板”只保存当前模板。也可在“设置”中选择运行风格、模式并保存。四份模板独立保存，其他模板草稿及设置页草稿不会随模板保存而提交或丢弃；未保存的模板草稿刷新后清除。“回到默认提示词”只恢复当前编辑的一份，仍需保存。
5. 在“概览”点击“立即总结并隐藏旧消息”手动运行，不受自动阈值限制；仍需有可处理的旧消息。只想压缩已有总结时点“仅合并已有总结”，不需要新增聊天。按钮上方显示实际已保存的模式、API 和保留数量，未保存的表单不会改变运行配置。token 是最近一次计数，可用旁边的刷新按钮重新组装计数。
6. 在“记录”中搜索、筛选并阅读当前注入内容或历史正文；“原文”显示模型原始输出，右上角按钮可复制或下载当前所选正文。需要恢复时，在“概览”展开“恢复与撤销”，可一次撤销并恢复本轮原文。关闭总开关时目录保持只读。

生成中断后，在概览展开“未完成的总结草稿”。正文只保存在当前浏览器和酒馆地址下，不随世界书同步到其他设备；清理浏览器站点数据会移除草稿。每个存档仅保留最新一份，下次生成收到新正文时更新；要保留多份可先下载。浏览器存储已满或不可用时会提示，正文留在本页供导出。突然断电或强制终止浏览器仍可能丢失最近尚未写入的片段。
7. 出现 mewo!! 时展开插件并点击“更新”，成功后自动刷新。旧版仍显示 New! 时，照常点更新即可。在支持扩展生命周期钩子的 ST 版本中，通过原有扩展管理页更新此插件也会自动刷新。

总结范围由提示词及 SillyTavern 当前生成上下文决定。阈值根据回复结束后酒馆组装的最终提示词计算，使用酒馆当前模型的 tokenizer。自定义聊天补全的提示词后处理也在计数前执行，不使用模型最大上下文容量作为 token 数。插件内会显示最近一次检查结果。

例如：开启自动总结后，本轮发送前为 59000 token，AI 回复后组装为 61000 token，则此时自动总结；保存并隐藏前文后重新计数，低于阈值后恢复下一次自动触发。打开已经达到 80000 token 的存档也会立即检查并触发。版本和署名位于展开区域，折叠时隐藏。

如果 API 或保存失败，会显示错误并解除发送锁；API 无正文或世界书未读回确认时不隐藏楼层。

### 总结范围与保留原文

假设恰好一问一答算一轮，没有额外开场白：聊到 50 轮，共 100 条消息，保留 20 条。普通总结会使用酒馆当前组装的完整上下文，包含最近 10 轮；保存成功后执行 `/hide 0-79`，保留第 80–99 层，也就是第 41–50 轮原文。最近剧情同时出现在总结和原文中，用于衔接与保留细节。

继续聊到 75 轮时，通常由已有总结、保留的第 41–50 轮原文及新增第 51–75 轮组成上下文。多次模式按模板提取新增剧情并追加；合并模式整理成新的完整总结。以上始终受酒馆当前可见消息、预设和上下文组装规则影响；插件不额外设置世界书预算限制。

“仅合并已有总结”是独立操作，只发送当前注入的总结及合并模板，不带当前聊天剧情。主/副 API 路由与生成参数照常沿用配置；普通总结的指令插入位置不用于这一专门操作。

### 恢复与分支

- **从当前原文重建（含隐藏消息）**：旧剧情已改动或输入覆盖检查失败时出现。使用当前存档全部原文重新生成，包含隐藏消息；会调用模型，成功后替换当前记忆，历史记录仍可查看。原文太长时仍需模型本身能够接收。
- **只重试隐藏**：用于正文已经保存、隐藏尚未完成或尚未确认的情况。直接完成那次隐藏，不重新付费生成。
- **撤销本次整理并恢复原文**：一次确认后撤销最近一次总结，再恢复本轮实际隐藏的消息；本次总结保留在历史中。部分恢复失败时显示“继续恢复本次原文”，重新打开聊天也可接着处理；若写入结果尚未确认，先用概览的“确认上次操作结果”同步状态。完成前暂停自动总结，不自动重发模型请求。
- **恢复本轮隐藏的消息**：仅恢复最近一次操作把可见改为隐藏的消息；原先已经隐藏的消息保持原样。它不删除总结，恢复后原文和总结可能同时进入上下文。
- **撤销最近一次总结**：恢复上一次的注入正文，保留本次 AI 正文供查阅。消息可见状态不变，需要时再恢复原文。自动总结会等待新的聊天消息，避免刚撤销就立刻重做。

恢复仅针对最近一次操作；新的总结或合并会替换这份恢复信息。修改原文、切换 swipe、手动执行 `/hide` 或 `/unhide` 后，自动恢复会拒绝覆盖后续操作。关闭总开关也会使旧的消息恢复失效，因为插件无法持续观察关闭期间的改动；仍可使用酒馆原生命令手动调整。手动修改世界书正文后，插件也不会用撤销结果覆盖它。

新分支单独保存总结，不会改写主线正文或历史。新记录会保存总结来源的终点与原文指纹，只有验证属于分支之前的内容才会继承。旧版记录只有隐藏终点，无法据此判断是否含分叉后的剧情，因此会提示“从分支原文重建（含隐藏消息）”，由用户点击后调用模型。重建会读取这个分支的全部消息原文，包括隐藏消息；消息少于保留数量时不执行隐藏。旧总结和历史仍保留在原存档中。

### 报错：Unexpected token '<' / DOCTYPE / 不是有效 JSON

这表示某个接口返回了 HTML 页面，却被当作 JSON 解析。可能是登录页、反向代理错误页或宿主不支持的路由；仅凭这条错误不能确定是哪一种。

如果手动总结能生成且记录可见，但自动总结和“只重试隐藏”失败，优先检查主连接的“自定义提示词后处理”：自动总结计数和隐藏前确认都会请求 `/api/backends/chat-completions/process`，生成成功并不代表这个预览接口可用。TauriTavern 用户可更新至 1.2.13，保留后处理设置，刷新计数，再对已保存的总结点击“只重试隐藏”，无需重新生成总结。普通 SillyTavern 应检查预览接口及代理路由。

错误提示会标明失败接口与 HTTP 状态；收到 HTML 时明确说明原因类别。若仍失败，请提供完整提示、宿主名称和版本、后处理模式及触发操作；管理员可检查该接口的状态码、响应类型、登录及代理路由。插件不会因预览失败而跳过隐藏前校验。

## 边界

- 自动触发针对角色卡的单人聊天；群聊不触发。
- 自动触发检查普通生成和会话续写；重试、再生成、滑动和后台静默生成不会触发总结。
- 计数来自酒馆组装后的上下文。自动阈值达到或超过主连接可用输入预算时可能无法触发，界面会提示；可按需增大上下文或调低阈值，插件不会自动改动。
- 普通总结检查发送正则/推理格式处理后的可见文本是否按顺序出现在宿主组装结果中，聊天补全在模板处理之前检查，文本补全使用最终数据事件。发送正则主动清空的文本不参与比较；后续模板改写、图片/附件内容与模型是否准确理解原文不属于此项验证。不能确认时保留原文；“仅合并”和“原文重建”直接提供指定资料，不使用普通聊天覆盖检查。
- 原文有效性检查使用已有记录的来源指纹。新增消息、隐藏和取消隐藏不使总结过时；缺少来源指纹的历史记录无法追溯验证。
- 副 API 默认支持 OpenAI 兼容接口，不包含原生 Anthropic/Gemini 接口。因为沿用酒馆原生生成流程，运行时需保持酒馆当前主连接可用；实际总结模型请求只发往副 API。上下文预算与阈值计数仍由当前酒馆配置决定，副模型需能容纳该上下文。

```powershell
playwright-cli run-code --filename tests/floating-panel-touch-browser.js
```

模拟页可使用 `?host=1.14` 测试旧世界书接口，或 `?host=tauri` 测试宿主标记与缺少新版 AbortSignal 静态方法的场景。它们不是真实酒馆客户端。固定源码核对可单独运行：

```sh
node scripts/fetch-compat-hosts.mjs
node --test tests/host-contracts.mjs
```

下载只写入忽略的 `output/hosts`，不改动任何用户酒馆；没有下载源码时，源码检查会明确标为 skipped。

隔离回归测试覆盖原有生成、命令、阈值、保存、主/副 API、提示词和更新流程；包括自动开关、无新消息合并、聊天/文本补全的独立资料输入、分支隔离与继承、重命名、取消、隐藏重试、撤销、刷新后的恢复、原文/swipe/手动可见性保护、元数据保存失败后的重试与幂等性，以及浮窗边界、手动模式下的显示刷新和阅读器的纯文本降级。1.2.1 增加截断与过滤响应、预算或正则拦截、注入确认后的隐藏重试、世界书切换回滚、取消挂起读回、响应体读取超时和读写次数回归。

最后一条命令启动 `http://127.0.0.1:8786/` 本地模拟宿主，可检查实际界面、深浅主题、窄屏和按钮流程。测试页包含酒馆 1.19.0 的 `menu_button` 最小内容宽度，用于发现中文按钮被挤窄的冲突。世界书在内存中，聊天与设置只保存在该测试页面的 localStorage；不连接真实酒馆，也不调用模型。结束时按 Ctrl+C 关闭服务。

可选第三个参数传入本机 SillyTavern 安装目录，例如 `node tests/ui-smoke.mjs 8786 "D:/path/to/SillyTavern"`，只读取该目录 `node_modules` 中的 DOMPurify 和 Showdown，用于验证格式化阅读；不指定时验证纯文本降级。测试页的“测试场景”可新建模拟存档，并模拟隐藏失败、世界书预算不足、模型回复截断、上下文裁剪或修改已总结的旧剧情。

`modules/summary-model.js` 保存纯数据规则，`source-coverage.js` 检查原文覆盖与阈值预算，`summary-prompt.js` 将总结任务与上下文资料分开，`world-book.js` 封装读写确认，`network.js` 管理请求取消与超时，`generation-validation.js` 检查响应完成状态与提示词正文，`task-state.js` 管理阶段文案，`settings.js` 和 `settings-ui.js` 管理配置及界面模板，`floating-panel.js` 管理悬浮窗口，`summary-reader.js` 处理安全阅读，`incomplete-drafts.js` 保存本地未完成正文，`text-export.js` 导出文本，`host-api.js` 集中酒馆内部导入。入口负责宿主事件与任务协调。

历史实现以 SillyTavern 官方 1.19.0 为参考；1.2.9 补查了 1.14.0–1.18.0 和固定 Canary 提交。分支身份使用聊天 `integrity` 字段；没有该字段的宿主按存档名变化保守隔离。回归测试和模拟宿主检查不代表真实宿主兼容性验证；用户实际安装版本、第三方插件组合和主/副 API 仍需在酒馆中验证。

隐藏前确认优先使用 `WORLDINFO_SCAN_DONE` 及世界书正则接口，1.14 使用两次 dry-run 来源确认。缺少两条验证路径时保留原文；第三方模板若进一步改写总结、导致无法确认完整正文，也会保守停止隐藏并说明原因。此检查确认当前预览的注入，不保证用户之后修改预算、预设或其他世界书时仍能注入。

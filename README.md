# 喵喵大总结

版本：0.3.2 | by NUE-喵喵电波

一个第三方 SillyTavern 前端扩展：使用当前主 API 在后台生成大总结，每个角色卡的聊天存档使用一个世界书条目，并在成功保存后隐藏已总结的旧楼层。

## 当前实现

- 打开聊天存档、启用插件及每次普通 AI 回复结束后，组装当前完整提示词并计算 token；达到默认 60000 阈值时立即开始后台大总结，无需用户再次发送。
- 每次超过阈值只触发一轮；隐藏楼层使上下文低于阈值后，下一次越过阈值才会再次触发，避免大总结自身很长时每轮重复总结。
- 默认保留最新 20 个聊天楼层，默认世界书名为“喵喵大总结世界书”；阈值、保留数量、插入深度、世界书名和提示词均可修改。升级保留已有世界书名称，避免原总结失去关联。
- 提供“多次大总结”和“合并大总结”两种模式，默认提示词使用用户提供的对应中文版本，支持 SillyTavern 宏。
- 两种模式分别保存自定义提示词。编辑后点击“保存修改提示词”生效；“恢复默认提示词”只更新编辑框，仍需保存。旧版自定义提示词保留在多次模式，未改动的旧 ELLA 默认提示词会更新为新默认。
- 总结通过酒馆原生 `Generate('quiet')` 流程运行，沿用 API 连接面板的主 API、当前模型和预设，并经过酒馆发送时的正则、世界书条件、扩展拦截器及 EJS/MVU 处理；不会新增可见聊天楼层。不抓取页面渲染出来的 HTML。
- 默认把大总结指令放在完整提示词最后，位于所有预设和 EJS 尾部内容之后，聊天补全中为最后一条 user 指令。也可选择角色定义之前、之后或聊天深度 @D，并选择 system/user/assistant；D0 + system 为系统层深度 0。层级注入使用酒馆原生接口，仅总结期间存在，完成、失败或切档后清理。
- 保存前读取酒馆当前“推理内容格式化”的前缀/后缀，去掉它们包裹的内容，保留外部正文（包括完整 `<details>`）。例如配置 `<star_cot>` 和 `</star_cot>`，该段不会写进世界书或本轮历史。只有推理、没有正文时不保存、不隐藏楼层。同步时也清理已有条目/历史中匹配当前完整推理标签的段落；没有可恢复正文的旧记录保留。
- 为兼容将自定义总结格式过滤为空的输出正则，仅观察本次总结对应的非流式 API 响应副本来提取正文；不额外调用模型、不输出响应日志，结束后恢复请求处理。
- 回复结束后的 token 检查、后台生成、世界书保存及隐藏楼层期间暂停发送；可以保留输入框中的草稿，完成后继续对话。
- “启用”开关切换后立即生效并保存到酒馆设置，重新打开保持上次选择，无需另点保存。取消勾选会取消待触发或正在运行的自动总结；手动总结仍可使用。
- 输入框中的所有 `/` 命令均交给酒馆原生解析，包括 `/hide`、`/unhide`、管道、宏、闭包及其他插件注册的命令。插件不代替解析、不清空命令输入、不等待生成事件释放锁。本地命令不会触发总结；命令若调用模型，在总结处理期间由酒馆原生生成拦截器取消该次模型生成，处理结束后可重新执行。酒馆本身正在生成时的输入限制仍由酒馆管理。
- 自动和手动总结都显示悬浮提示：正在大总结、正在保存、保存成功、完成或失败。生成/保存阶段的提示持续显示，处理结束后清理；正文读回确认成功后才提示保存成功。已保存但后续处理失败时明确说明总结记录已保存。
- 生成后及正式保存前检查聊天身份和原楼层；切档或手动调整楼层时不会将过时结果写入世界书，也不会继续自动隐藏。若保存之后发生变化，保留已保存记录并提示没有隐藏楼层。
- 多次模式：每轮只总结新增剧情，并追加到同一聊天档的原条目。第二次、第三次继续写进第一次创建的条目，注入正文包含累积总结。
- 合并模式：每轮将已有总结和新增剧情汇总，使用新 AI 回复替换同一条目的注入正文。切换模式从下一轮生效。
- 每轮 AI 正文保存在条目内部的历史记录中，目录可以查看当前注入全文或逐轮正文，并删除单轮或整个存档的总结。删除单轮会按剩余历史重建正文，已隐藏的聊天楼层不会自动恢复。
- 切换角色卡或聊天存档时，真正禁用其他档的条目，仅当前档的条目蓝灯启用；同步结束前暂停发送，并刷新已经打开的世界书编辑器。
- 新建及已有大总结条目统一勾选“防止进一步递归”。旧版同一聊天档的多个条目自动迁入原条目，历史 AI 原文保留。
- 总结返回非空内容并成功保存世界书后，才执行 `/hide 0-楼层号`。聊天记录不会被删除，最近设置数量的楼层不会隐藏。
- UI 分为“设置 / 提示词 / 总结目录”。目录支持搜索、角色筛选，每页最多 8 个角色，默认仅展开当前角色，并限制目录高度。
- 设置增加“保存设置”和“恢复默认设置”。除“启用”开关外，修改或恢复默认后需保存才生效；提示词有独立的保存/默认按钮。刷新状态按钮固定横排。
- 启动时检查 Git 更新，有更新时标题显示 New!，展开后显示版本和更新按钮；也可手动检查。由用户点击更新，成功后等待当前生成/总结处理完成，再自动刷新 ST，暂存并恢复聊天输入框的草稿。

## 安装

仓库地址：<https://github.com/AYUUKI-K/Mewo-Large-Summary>。在 SillyTavern 的“扩展”页面使用“安装扩展”并粘贴该仓库 URL。扩展后续版本可在 SillyTavern 页面检查，由用户选择是否更新。

## 使用

1. 在“设置”中勾选“启用”，开关立即生效并保存。确认世界书名称、60000 token 阈值、保留楼层数、世界书插入深度、总结模式和指令位置，修改这些设置后点击“保存设置”。“恢复默认设置”只更新表单，仍需保存，不重置提示词或删除已有总结。
2. 不需要手动创建世界书。第一次大总结会自动创建并挂载到全局世界书；已有同名书继续使用，其中的其他插件或手写条目不会被覆盖。页面显示创建和挂载状态，可点击“刷新状态”查看。
3. 在“提示词”分页选择要编辑的模式，编辑后点击“保存修改提示词”。实际运行模式在“设置”中选择并保存；不同模式的未保存提示词草稿在本次页面会话中保留。
4. 在“总结目录”中搜索、筛选、查看和删除总结。也可以在“设置”中点击“立即大总结”手动运行，即使自动触发关闭也可使用。
5. 出现 New! 时展开插件并点击“更新”，成功后自动刷新。首次升级到 0.3.0 需先在酒馆原有扩展管理页更新并刷新，之后可使用插件内按钮。在支持扩展生命周期钩子的 ST 版本中，通过原有扩展管理页更新此插件也会自动刷新。

总结范围由提示词及 SillyTavern 当前生成上下文决定。阈值根据回复结束后酒馆组装的最终提示词计算，使用酒馆当前模型的 tokenizer。自定义聊天补全的提示词后处理也在计数前执行，不使用模型最大上下文容量作为 token 数。插件内会显示最近一次检查结果。

例如：本轮发送前为 59000 token，AI 回复后组装为 61000 token，则此时自动总结；保存并隐藏前文后重新计数，低于阈值后恢复下一次自动触发。打开已经达到 80000 token 的存档也会立即检查并触发。版本和署名位于展开区域，折叠时隐藏。

如果 API 或保存失败，会显示错误并解除发送锁；API 无正文或世界书未读回确认时不隐藏楼层。

## 边界

- 自动触发针对角色卡的单人聊天；群聊不触发。
- 自动触发检查普通生成和会话续写；重试、再生成、滑动和后台静默生成不会触发总结。
- 如果主模型的最大上下文小于阈值，触发条件无法达到，可调低阈值。
